# Postgres connections are a budget of 15, not a server cap

PHP PDO does not multiplex. Each worker holds one session. `DB_POOL_SIZE=15` is that worker/PgBouncer budget, documented in `config/database.php`. Postgres `max_connections` stays higher (Compose uses 100) so admin and migrations still fit. Persistent PDO connections stay off: they hide dead sockets and skip session GUCs. Production SSL is `require`; local is `prefer`. Sessions get `application_name`, UTC, read committed, `statement_timeout` 15s, `idle_in_transaction_session_timeout` 30s, `lock_timeout` 5s, connect timeout 5s. Native prepares stay on until PgBouncer transaction pooling (`DB_PGBOUNCER=true` then emulates prepares). A real pooler is still the scale step; this config is the contract the pooler must honour.
