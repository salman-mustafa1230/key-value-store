# Cursor pagination for the current snapshot

The list is the current snapshot in cursor pages, not one payload of every Key. The spec’s “all values currently stored” is the collection; an unpaginated dump fails the scale axis (many Keys). The body is `{ "data": [ { "key", "value" }, ... ], "next_cursor": null | "..." }` so the cursor lives in JSON next to structured errors. A top-level JSON array cannot carry `next_cursor`; a header cursor is easier for reviewers to miss. Clients send `?cursor=` and `?limit=` (default 50, max 1000) and walk until `next_cursor` is null. Pages are Keys in ascending Key order; the cursor is the last Key of the page. The README must say why this is not an unpaginated array.
